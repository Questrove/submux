# 输出产物更新使用持久的逐订阅状态机

来源、节点、模板、规则方案或平台设置发生变化时，submux 不回滚已经生效的领域状态，也不再通过全量 `RebuildAll` 尝试维持产物一致性；数据库 v10 在同一个 bbolt 事务中精确标记受影响且已启用的输出订阅为产物待更新，并递增各自的输入代次。独立的输出产物更新 module 在事务提交后同步尝试一次，再以全局串行、持久化和分类退避的方式继续处理，只允许当前代次的编译结果替换最近可用产物；产物与更新状态分开保存，compiler 只负责编译。新建、编辑和启用输出订阅必须先编译成功再原子提交；预编译前读取只用于提交校验的全局输入版本，提交时同时核对该版本和订阅记录版本，版本变化就丢弃结果并重新编译或返回并发冲突，这个全局版本不改变逐订阅的精确失效范围。现有产物在普通失败时继续交付，生命周期阻断仍拒绝交付，详细失败只对管理端可见；停用订阅不自动更新，删除优先，v9 迁移后对全部已启用订阅执行一次非阻塞校准，并删除 `CompileAndStore`、`RebuildAll` 与 `Fetcher.SetRebuilder`，不保留第二条运行路径。
