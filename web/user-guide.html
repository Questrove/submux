从安装到卸载，按实际操作顺序说明

01 · 选择产品

先确定你需要安装什么

两个产品可以独立安装。控制面负责整理和发布配置，Runtime 负责在一台机器上管理 Mihomo 和网络接管。

submux 控制面

生成输出订阅

适合管理机场来源、自建节点、模板与规则，并为不同设备生成 Mihomo 或 sing-box 配置。

  • 提供浏览器管理页面
  • 不运行代理核心
  • 可部署在服务器，也可在本机使用
Submux Runtime

在本机运行代理

适合管理一个官方 Mihomo，接收完整配置，并提供显式代理、TUN 和 Linux 网关。

  • GUI、TUI、CLI 都通过本机 IPC 管理
  • 支持配置校验和失败恢复
  • 不会接受控制面远程操作
1添加机场来源或自建节点
2选择模板与规则
3生成输出订阅
4Runtime 添加该地址
5校验后启动 Mihomo
02 · 安装前

准备系统、权限和安装包

确认系统支持
Linux 需要 systemd 与 glibc；macOS 需要 13 或更高版本；Windows 需要受支持版本和 WebView2。
选择正确架构
Windows 和 Linux 选择 amd64 或 arm64。macOS Runtime 使用 Universal 安装包。
保留校验文件
安装前用发行页提供的 SHA-256 检查下载文件，校验不一致时不要继续。
准备管理员权限
Runtime 是机器服务。安装、授权桌面用户和网络接管都需要管理员确认。
当前签名状态：Windows Runtime MSI 尚未签名，可能显示 Unknown Publisher；macOS PKG 尚未签名和公证。Runtime 仍处于 Preview，请先在可恢复的环境中使用。
03 · 安装

按操作系统安装

下面默认安装 v2.0.2。在线 Runtime 包不含 Mihomo，安装服务后还要执行“安装 Mihomo”步骤；完整离线包已经包含固定版本的官方 Mihomo。

安装控制面

安装固定版本并创建 submux.service。

curl -fsSL \
  https://github.com/Questrove/submux/releases/download/submux-v2.0.2/install-submux.sh | \
  bash -s -- --version submux-v2.0.2 --service
systemctl status submux

安装 Runtime

桌面机器建议安装时授权当前用户，服务器可以不加授权变量。

# Debian / Ubuntu
sudo env SUBMUX_RUNTIME_AUTHORIZE_USER="$USER" \
  dpkg -i submux-runtime_2.0.2_amd64_online.deb

# Fedora / RHEL
sudo env SUBMUX_RUNTIME_AUTHORIZE_USER="$USER" \
  rpm -Uvh submux-runtime_2.0.2_amd64_online.rpm

其他 systemd / glibc 发行版可解压 online.tar.zst，然后执行其中的 sudo ./install.sh --authorize-desktop "$USER"。

在线安装 Mihomo

PLAN_ID="$(sudo submux-runtime mihomo check --json | \
  sed -n 's/.*"plan_id":"\([^"]*\)".*/\1/p')"
test -n "$PLAN_ID"
sudo submux-runtime mihomo install \
  --plan "$PLAN_ID" --trust tuf --confirm --wait --json

检查服务

systemctl status submux-runtime submux-runtime-net
sudo submux-runtime status --json

安装后才授权桌面用户时，执行 sudo submux-runtime-authorize-user --confirm "$USER"，然后重新登录。

完全离线：使用 Linux airgap 包

airgap 包可以只装控制面、只装 Runtime 或全部安装，目标机器不需要访问网络。

sha256sum --check submux-airgap_2.0.2_linux_amd64.tar.gz.sha256
tar -xzf submux-airgap_2.0.2_linux_amd64.tar.gz
cd submux-airgap_2.0.2_linux_amd64
./install.sh verify
sudo ./install.sh all
# 或：sudo ./install.sh control
# 或：sudo ./install.sh runtime --authorize-desktop "$USER"

下载并运行控制面

从 控制面发行页下载对应架构的 exe 与 checksums.txt。校验后直接运行；当前不会注册为 Windows Service。

$Program = 'submux-windows-amd64.exe'
$Line = (Get-Content checksums.txt | Select-String \
  ('  ' + [regex]::Escape($Program) + '$')).Line
$Expected = ($Line -split '\s+')[0]
$Actual = (Get-FileHash $Program -Algorithm SHA256).Hash
if ($Actual.ToLower() -ne $Expected.ToLower()) { throw 'checksum mismatch' }
& ".\$Program"

安装 Runtime MSI

下载 online MSI 和对应的 .sha256，核对后以管理员权限安装。参数会授权当前用户。

$Package = 'submux-runtime_2.0.2_amd64_online.msi'
$Expected = ((Get-Content "$Package.sha256") -split '\s+')[0]
$Actual = (Get-FileHash $Package -Algorithm SHA256).Hash
if ($Actual.ToLower() -ne $Expected.ToLower()) { throw 'checksum mismatch' }
$MsiPath = (Resolve-Path $Package).Path
Start-Process msiexec.exe -Verb RunAs -Wait -ArgumentList @(
  '/i', "`"$MsiPath`"", 'AUTHORIZE_CURRENT_USER=1'
)

在线安装 Mihomo

$Runtime = "$env:ProgramFiles\Submux Runtime\submux-runtime.exe"
$Plan = (& $Runtime mihomo check --json | Out-String | ConvertFrom-Json)
& $Runtime mihomo install \
  --plan $Plan.plan_id --trust tuf --confirm --wait --json
& $Runtime status --json
完全离线：使用 offline MSI

还要下载 offline-verification-bundle.zip 和 SHA256SUMS。分别校验后安装 MSI，再执行：

$Runtime = "$env:ProgramFiles\Submux Runtime\submux-runtime.exe"
$Plan = (& $Runtime mihomo import --json .\offline-verification-bundle.zip |
  Out-String | ConvertFrom-Json)
& $Runtime mihomo install \
  --plan $Plan.plan_id --trust tuf --confirm --wait --json

安装控制面

程序安装到 /usr/local/bin/submux，不会创建 LaunchDaemon。

curl -fsSL \
  https://github.com/Questrove/submux/releases/download/submux-v2.0.2/install-submux.sh | \
  bash -s -- --version submux-v2.0.2
submux

安装 Runtime PKG 并授权用户

PACKAGE="submux-runtime_2.0.2_universal_online_unsigned.pkg"
shasum -a 256 -c "${PACKAGE}.sha256"
sudo installer -pkg "$PACKAGE" -target /
sudo /usr/local/sbin/submux-runtime-authorize-user --confirm "$USER"

在线安装 Mihomo

PLAN_ID="$(submux-runtime mihomo check --json | \
  sed -n 's/.*"plan_id":"\([^"]*\)".*/\1/p')"
test -n "$PLAN_ID"
submux-runtime mihomo install \
  --plan "$PLAN_ID" --trust tuf --confirm --wait --json
submux-runtime status --json
完全离线：使用 offline PKG

下载 Universal offline PKG、摘要、offline-verification-bundle.zip 与 SHA256SUMS，全部校验后安装并授权当前用户。

submux-runtime mihomo import --json ./offline-verification-bundle.zip
# 从上一步 JSON 中取得 plan_id 后执行：
submux-runtime mihomo install \
  --plan PLAN_ID --trust tuf --confirm --wait --json
04 · 首次使用

先生成配置，再明确启动代理

控制面：创建输出订阅

Linux 服务默认监听 127.0.0.1:8080。第一次打开时设置管理员密码，然后按页面顺序完成：

  1. 添加机场来源或导入自建节点
  2. 检查统一节点库
  3. 选择或发布模板
  4. 建立规则方案
  5. 生成输出订阅并复制地址
注意：输出订阅 token 相当于访问凭据。对外提供地址时请使用 HTTPS，不要公开粘贴到日志或截图。

Runtime：添加配置来源

Runtime 可以保存多个来源，但任意时刻只有一个当前来源。

  1. 添加远程地址或导入本机副本
  2. 应用并检查候选配置
  3. 选择显式代理、TUN 或 Linux 网关
  4. 预览网络改动
  5. 明确启动代理
默认状态：Mihomo 停止，路由和 DNS 不会改变。添加、刷新或导入来源不会自动启动代理。

使用 TUI 完成首次配置

在交互式终端运行 submux-runtime 或 submux-runtime tui。状态页会根据 Runtime Snapshot 显示六个步骤，并保留已经完成的结果：

检查服务与本机权限

确认 Runtime 正在运行、当前用户已经获准访问本机 IPC；权限不足时先使用上面的平台授权命令。

安装官方 Mihomo 核心

在维护页按 U 检查核心，检查完成后再按一次 U，核对统一确认中的目标、影响、中断和恢复方式，再按 Enter。

添加 Runtime 配置来源

切到配置页，按 u 添加远程来源或按 n 导入本机副本；表单用 Tab 移动，Ctrl+S 提交，Esc 取消。

生成并校验候选配置

在“配置来源”区域用 ↑↓ 选择来源，按 Enter 或 y 生成候选。此时不会切换当前来源。

预览运行方式

进入网络页，按 Ctrl+P、Ctrl+T 或 Ctrl+L 选择显式代理、普通 TUN 或 Linux 网关。先生成预览，核对当前实际、预期结果、DNS、路由、冲突和恢复动作。

明确应用并启动

按 Ctrl+E 应用已经确认的网络预览，或按 s 启动显式代理。所有状态修改都会先进入统一确认；Enter 确认，Esc 取消。

把控制面输出订阅交给 Runtime

submux-runtime source add \
  --type submux_output \
  --name submux-main \
  --url 'https://sub.example.com/sub/replace-with-token' \
  --wait --json
submux-runtime source list --json
SOURCE_ID='把 source add 输出中的 source_id 填在这里'
submux-runtime source apply --wait --json "$SOURCE_ID"
submux-runtime proxy start --wait --json
submux-runtime proxy verify --json
没有远程地址：导入本机 Mihomo 配置

导入后 Runtime 保存自己的副本，不会继续监视原文件。

submux-runtime source import --name local-config --wait --json ./config.yaml
submux-runtime source list --json
SOURCE_ID='把 source import 输出中的 source_id 填在这里'
submux-runtime source apply --wait --json "$SOURCE_ID"
submux-runtime proxy start --wait --json
05 · 日常使用

常用入口和操作

在交互式终端直接运行 submux-runtime 会进入 TUI，也可以使用 GUI。GUI、TUI 和 CLI 的管理能力相同；退出 GUI 不会停止 Runtime、Mihomo、TUN 或网关。

TUI 的五个页面

按键页面主要内容与操作
1状态运行状态、当前来源、最近运行操作、主要代理组；Enter 查看当前焦点详情。
2配置来源、候选配置、本机运行设置、最终规则、代理组与节点；↑↓ 选择来源，t 切换，Ctrl+N 选择节点。
3网络当前网络、网络预览和网络操作；Ctrl+P/T/L 预览运行方式，Ctrl+E 应用，Ctrl+X 停用并恢复直连。
4监控当前上传下载速度、本次运行累计、1/5/15 分钟速度曲线、活动连接和 Runtime 事件；[/] 切换曲线范围。
5维护更新与回滚、备份恢复、诊断、运行操作和脱敏日志。

查看整体状态

检查当前来源、Mihomo、期望运行状态、网络接管和最近故障。

submux-runtime status
submux-runtime status --json

启动、验证和停止

停止代理时，Runtime 会先撤销自己创建的网络设置。

submux-runtime proxy start --wait
submux-runtime proxy verify
submux-runtime proxy stop --wait

预览并启用 TUN

先查看计划和冲突，再使用返回的 plan ID。

submux-runtime network preview --mode tun
submux-runtime network enable \
  --mode tun --plan-id PLAN_ID --wait
submux-runtime network disable --mode tun --wait

刷新当前来源

刷新失败时继续使用最近可用配置，不会自动切换来源。

submux-runtime source list
submux-runtime source refresh --wait SOURCE_ID
submux-runtime source apply --wait SOURCE_ID
运行方式：显式代理不修改系统网络。TUN 适合桌面机器；Linux 网关用于接管指定局域网流量，第一版不代理 IPv6，正式使用前必须完成真实网络验收。

06 · 维护

更新、诊断和备份

更新与修复

Runtime 可以检查更新，但不会在后台自动安装。TUI 维护页中 U 管理 Mihomo，P 管理 Runtime 产品；首次按键只检查，再按一次才进入统一确认。升级默认保留状态；同版本重装需要明确选择“修复”。

sudo ./install.sh runtime --repair
sudo ./install.sh runtime \
  --allow-downgrade --database-compatible

本机诊断包

诊断包只在本机生成，不会上传。默认内容已经脱敏。

submux-runtime diagnostics preview
submux-runtime diagnostics create

Runtime 与 Mihomo 日志默认保留 7 天或 50 MiB。

创建可恢复备份

可恢复备份会包含凭据，是未加密的明文文件。

submux-runtime backup preview --include-secrets
submux-runtime backup export --include-secrets \
  --confirm-plaintext ./submux-runtime.backup

检查并恢复备份

恢复会整体替换可迁移状态，不和当前配置合并。

submux-runtime backup inspect ./submux-runtime.backup
submux-runtime backup restore --confirm --wait \
  ./submux-runtime.backup
07 · 卸载

先恢复直连，再卸载程序

卸载不由正在运行的 TUI 执行。先在维护页用 B 创建完整明文备份，进入网络页按 Ctrl+X 准备停用网络接管并在统一确认中按 Enter；确认状态页已经恢复直连后按 q 退出 TUI，再运行对应平台的卸载器。卸载器会先停止主 Runtime，再停止特权网络进程，并检查路由、DNS、防火墙、TUN、服务和 Socket 是否有残留。发现残留时卸载会失败，也不会继续清除状态。

清除数据无法撤销。默认卸载会保留配置和状态。只有确认不再需要来源、凭据、覆盖和最近可用配置时，才使用 purge。
安装方式保留状态同时清除状态
DEBsudo dpkg -r submux-runtimesudo dpkg -P submux-runtime
RPMsudo rpm -e submux-runtimesudo env SUBMUX_RUNTIME_PURGE=1 rpm -e submux-runtime
tar.zstsudo ./install.sh --uninstallsudo ./install.sh --uninstall --purge

默认保留 /etc/submux-runtime、/var/lib/submux-runtime 和 /var/lib/submux-runtime-privileged。

powershell -File .\Uninstall-SubmuxRuntime.ps1
# 同时清除 %ProgramData%\SubmuxRuntime
powershell -File .\Uninstall-SubmuxRuntime.ps1 -Purge

控制面不是 Windows Service。关闭程序后删除 exe；若使用自定义数据库路径，请自行决定是否保留数据库文件。

sudo /usr/local/sbin/submux-runtime-uninstall
# 同时清除 Runtime 状态
sudo /usr/local/sbin/submux-runtime-uninstall --purge

卸载控制面

Linux 或 macOS 使用同一个安装脚本。Linux 会移除由安装器管理的 systemd unit，但保留 /var/lib/submux。

curl -fsSL \
  https://github.com/Questrove/submux/releases/download/submux-v2.0.2/install-submux.sh | \
  bash -s -- --uninstall
08 · 排查

常见问题

添加来源后为什么没有代理？
添加、刷新和导入来源都不会自动启动 Mihomo。先执行 source apply，再执行 proxy start --wait，最后用 proxy verify 检查。
CLI 提示无权限或无法连接 Runtime
先确认服务正在运行。Linux 用户加入操作员组后需要重新登录；macOS 执行授权命令；Windows 安装 MSI 时使用 AUTHORIZE_CURRENT_USER=1。
在线安装包中找不到 Mihomo
online 包只安装 Runtime，之后需要执行 mihomo check 和 mihomo install。无法访问官方发行位置时改用完整离线包。
启用 TUN 或网关时报冲突
重新执行 network preview，检查已有 VPN、其他代理、DNS 管理程序和默认路由。只有预览符合预期时才使用对应 plan ID 启用。
Runtime 连续崩溃后不再自动重启 Mihomo
十分钟内自动重试达到上限后会进入“需要处理”状态，并保持直连。查看 submux-runtime status 和诊断包，修正问题后再手动启动。
卸载失败并提示网络残留
卸载器会停止清理，避免删除状态后留下不可追踪的网络修改。先确认 Runtime 创建的服务、路由、DNS、防火墙、TUN 和 Socket 已撤销，再重试。
